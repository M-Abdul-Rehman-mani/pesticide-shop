# Database

PostgreSQL 16 is the supported primary database. There is no SQLite engine or offline
fallback. UUID primary keys, `TIMESTAMPTZ`, foreign keys, indexes, check constraints, and
`NUMERIC(16,2)` money columns are used throughout.

## Main aggregates

- `users`, `customers`, `suppliers`, `products`
- `purchases` -> `purchase_items` -> `phone_inventory`
- `sales` -> `sale_items` -> `payments`
- `sale_returns` -> `return_items` -> refund `payments`
- `damage_records`
- append-only `inventory_transactions` and `audit_logs`
- `email_history`, `app_settings`, and `document_sequences`

Completed business documents are never hard-deleted. PostgreSQL triggers reject update/delete
operations on immutable ledger rows and reject deletes from completed sales, returns,
purchases, payments, and damage history. Corrections use return, void, cancel, or audited
adjustment operations.

## Migrations

From an activated environment:

```bash
alembic upgrade head
alembic current
alembic check
alembic revision --autogenerate -m "describe the change"
```

Review every autogenerated revision, especially enum and trigger changes. Apply migrations
before starting a new desktop build. The application compares `alembic_version` with its
packaged migration head and refuses to open against an outdated schema.

## Test isolation

The Compose profile exposes `mobile_shop_test` on port 5433. Pytest refuses any database name
that does not end in `_test`, migrates it to head, and wraps each test in a transaction.

## Indexes

Exact IMEI and invoice lookups use unique B-tree indexes. Composite indexes cover product and
status, transaction history, document dates, customers, suppliers, email queue status, and
audit/entity searches. Search filters are translated to PostgreSQL queries before pagination.
